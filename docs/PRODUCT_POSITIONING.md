# DinoVoyage 产品定位书

> 本文档基于产品访谈对话凝练而成，定义了 DinoVoyage 的产品方向、核心形态与 MVP 边界。
> **后续所有功能决策、设计取舍、技术选型，均以此文档为准绳。** 如需修订，须同步更新本文档。

---

## 1. 产品身份

### 一句话定位

> **以演化谱系为骨架、用户可参与共建的恐龙知识档案馆与渐进式学习工具，通过博物馆经营与时空穿梭的游戏化包装，让用户在探索中掌握古生物知识。**

### 产品名

DinoVoyage（恐龙之旅）

### 终极目标

上架 App Store，成为恐龙/古生物爱好者群体的首选知识工具。

---

## 2. 目标用户

**核心用户**：恐龙爱好者、古生物爱好者（以用户自身为代表的人群）

用户画像关键词：
- 对恐龙有真实兴趣，不只是猎奇
- 会主动通过书籍、B 站视频、电影等渠道获取恐龙知识
- 偏好科学向内容（科学复原、演化谱系、化石证据），但不排斥视觉表现力
- 目前市面上缺乏能满足这类用户的知识型 App

---

## 3. 差异化与护城河

### 与现有信息渠道的对比

| 渠道 | 特征 | DinoVoyage 的不同 |
|---|---|---|
| B 站视频 | 一次消费，故事性强，被算法投喂 | **可反复使用**，结构化知识体系，用户主导探索节奏 |
| 恐龙书籍 | 线性阅读，不便检索与跳转 | **按演化关系自由跳转**，数据可对比、可筛选、可标记 |
| 电影/游戏 | 视觉震撼，科学准确性参差不齐 | **基于科学研究**，但保留视觉品质与互动趣味 |
| 其他恐龙 App | 市场几乎空白 | 你是填补空白 |

### 内容护城河

- **结构化**：不是内容的堆砌，而是以演化谱系为骨架、以时空/地域为维度的知识网络
- **可复用**：用户可反复回来查阅、对比、标记进度，而非"看过就划走"
- **参与感**：用户不只是被动接收者，而是博物馆的经营者、知识的收集者

## 4. 产品形态

### 三层结构（C 为主，B 次之，A 为辅）

```
        ┌──────────────────────────────────────┐
        │   🏛️ 私人知识档案馆（核心·C 层）      │
        │   用户在探索中收集恐龙数据，           │
        │   系统按演化谱系自动归类，             │
        │   形成个人专属的恐龙知识库             │
        │                                      │
        │   ┌────────────────────────────┐     │
        │   │ 📖 结构化学习路径（B 层）   │     │
        │   │   沿演化树逐类解锁，         │     │
        │   │   学完打勾标记进度，         │     │
        │   │   像"集邮"一样填满演化树     │     │
        │   └────────────────────────────┘     │
        │                                      │
        │   ┌──────────────┐                   │
        │   │ 🎮 游戏化激励（A 层）│              │
        │   │   答题辨别恐龙，       │              │
        │   │   解锁徽章与展品       │              │
        │   └──────────────┘                   │
        └──────────────────────────────────────┘
```

### 游戏化叙事包装

上述三层，通过以下两个核心概念串联：

| 概念 | 包装了什么 | 用户感知 |
|---|---|---|
| 🏛️ **我的博物馆** | 知识档案馆 + 学习进度 | 收集的恐龙变成展品，演化树变成展厅分类 |
| ⏰ **时空穿梭机** | 知识获取 + 恐龙辨别训练 | "回到恐龙时代"，通过观察特征辨识恐龙，解锁展品 |

## 5. 核心体验流程

```
用户打开 App
  │
  ├─ 🏛️ 我的博物馆
  │   初始状态：一块空地，入口处孤零零一只入门恐龙
  │   演化树作为"展厅地图"，按时代/类群分区
  │   每获取新恐龙 → 展区自动扩充
  │
  └─ ⏰ 时空穿梭机
      选择目的地：时代 + 地域（如：白垩纪晚期 · 北美洲）
      ↓
      进入 2D 手绘场景（森林/平原/海岸）
      远处出现几只恐龙的剪影/轮廓
      ↓
      靠近一只 → 弹出观察界面（特征观察）
      用户根据特征判断种类：
        - 前肢指头数？
        - 体长估算？
        - 头部/角/冠特征？
        - 牙齿形态暗示的食性？
      → 选择答案
      ↓
      辨别成功 → 恐龙解锁！
      完整的科学数据、复原图、化石信息自动归档
      ↓
      回到博物馆 → 新展区已就位
      演化树上对应节点点亮
```

## 6. 技术路线

### 技术栈

| 层级 | 选型 |
|---|---|
| 框架 | Next.js 16（App Router） |
| 语言 | TypeScript |
| 样式 | Tailwind CSS 4 |
| 游戏化渲染 | Canvas / SVG + Framer Motion |
| 数据层 | MVP 阶段本地 JSON，后续可接入数据库 |
| 部署 | Vercel（渐进式，最终可封装为移动端 App） |

### 路线选择

选择 **Web 游戏化路线**（而非 Unity/Unreal 游戏引擎路线）：

- ✅ 可以做：2D 手绘场景、特征辨别玩法、博物馆收集系统、答题闯关、演化树可视化
- ❌ 不做：自由 3D 行走、电影级恐龙动画、实时物理模拟

## 7. MVP 边界（待精细化确认）

### 第一版必须包含

- [ ] 演化树框架（作为知识导航骨架）
- [ ] 时空穿梭探索玩法（至少一个时代场景）
- [ ] 恐龙特征辨别机制（至少一种交互形式）
- [ ] 我的博物馆（基本放置/收集系统）
- [ ] 恐龙档案卡片（标准化数据模板）
- [ ] 预置恐龙数据（数量待定）

### 第一版明确不做

- [ ] 用户系统/账号/登录
- [ ] 社交功能（评论、分享、排行）
- [ ] 自由 3D 场景
- [ ] 多语言/国际化
- [ ] 后台管理/CMS
- [ ] 真·数据库（先用本地 JSON）
- [ ] 内容 UGC（用户上传内容）

### 待决策项

- 第一版内容范围：一只极致深度 / 一个生态群 / 一条演化线 / 全谱系广度
- 第一版时空穿梭场景数量
- 移动端适配优先级（先桌面端 or 直接移动优先）

## 8. 设计原则

1. **科学准确优先于视觉炫技**：数据来源需可靠，不确定处标注"假说"
2. **探索驱动而非说教**：用户通过"做"（穿梭、辨别、收集）来学，而非被动阅读
3. **演化关系是骨架**：每一处设计都应强化"恐龙之间的演化关联"，而非孤立展示
4. **反复使用而非一次消费**：每次打开都有新东西可做、可查、可对比
5. **渐进式复杂度**：入门简单（霸王龙谁不认识？），深度有空间（演化谱系的细节）
